# Keep mounted vs unmount

When the user leaves a screen, you can keep it mounted (hidden) or unmount it.

| | Keep mounted | Unmount |
| --- | --- | --- |
| Going back | Instant; scroll position and focus are still there | Rebuild the screen, refetch or read from cache |
| Focus restore | Free, the element still exists | Must restore by item id (see [Remote and focus](../docs/02-remote-and-focus.md#restore-focus-by-item-id-when-returning-to-a-screen)) |
| Memory | Images, lists, and state stay in memory | Freed |
| CPU | Timers, subscriptions, and re-renders may keep running | None |
| Focus risk | Hidden focusables can still be found by focus (especially on web) | None |

TVs often have 1–2 GB of RAM shared with video decoding, so memory is the main cost. Images are the biggest part of it.

If you keep a screen mounted:

- **Make it unfocusable while hidden.** On web, pause or remove its focusables (e.g. a `focusable: false` / paused parent in Norigin), or it can steal focus from the active screen. On native, make sure hidden screens are detached from the view tree (react-native-screens does this for inactive stack screens).
- **Pause its work**: timers, polling, autoplaying previews (`useIsFocused` in React Navigation).
- **Release big images** you don't need to see right now if memory is tight.
