# Login on TV: QR code or code entered on a phone

Typing an email and password with a D-pad on an on-screen keyboard takes minutes. Move the typing to the phone.

**Device code flow** (OAuth 2.0 Device Authorization Grant, RFC 8628):

1. The TV asks the server for a code: gets `user_code` (e.g. `HJK-492`), a `verification_uri`, an `expires_in`, and a polling `interval`.
2. The TV shows:
   - A **QR code** of the URL with the code already in it (`verification_uri_complete`), for scanning with the phone camera.
   - The **short URL and the code** in big text, for users who type it on a phone or laptop.
3. The TV **polls** the token endpoint every `interval` seconds while the user signs in on the phone.
4. When the server returns tokens, the TV moves on to the profile picker / home screen.

Details to get right:

- **Expiry.** When the code expires, fetch a new one automatically and update the screen. Don't show an error.
- **Respect `slow_down`** from the server and increase the interval.
- **Stop polling** when the user leaves the screen or the app is suspended; restart on resume.
- **Codes must be easy to read and type**: short, upper case, no `0/O`, `1/I/L`.
- Keep a **fallback** (email/password on the TV) only if you must, and make it the second option.
- Store tokens in secure storage on native; on web TVs, check what the platform offers.
