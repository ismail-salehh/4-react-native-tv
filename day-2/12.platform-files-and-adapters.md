# Platform files and adapters

### Resolution order

Bundlers pick a file by its extension, trying the most specific first. For an import of `./Player`:

| Build | Tries, in order |
| --- | --- |
| Samsung (webpack) | `Player.tizen.web.tsx` → `Player.web.tsx` → `Player.tsx` |
| LG (webpack) | `Player.webos.web.tsx` → `Player.web.tsx` → `Player.tsx` |
| Android TV (Metro) | `Player.android.tsx` → `Player.native.tsx` → `Player.tsx` |
| Apple TV (Metro) | `Player.ios.tsx` → `Player.native.tsx` → `Player.tsx` |

So **`.tizen.web.tsx` beats `.web.tsx` beats `.tsx`**. The first match wins, and the others are not bundled.

For web, this order comes from `resolve.extensions` in the webpack config, set per target:

```js
// webpack.config.js
const target = process.env.TV_TARGET; // 'tizen' | 'webos'

module.exports = {
  resolve: {
    extensions: [
      `.${target}.web.tsx`, `.${target}.web.ts`,
      '.web.tsx', '.web.ts',
      '.tsx', '.ts', '.js',
    ],
  },
};
```

### Keep platform checks out of feature code (web)

Feature code (screens, rails, details) should never ask "am I on Samsung?":

```tsx
// Bad: in a screen
if (isTizen) {
  webapis.avplay.open(url);
} else if (Platform.OS === 'web') {
  videoRef.current.src = url;
} else {
  ...
}
```

Instead, put each platform difference behind an **adapter**: one interface, one file per platform.

```ts
// player/types.ts
export interface PlayerAdapter {
  load(url: string): Promise<void>;
  play(): void;
  pause(): void;
  seek(seconds: number): void;
}
```

```
player/
  Player.tsx             // native: react-native-video
  Player.web.tsx         // LG and generic web: <video>
  Player.tizen.web.tsx   // Samsung: AVPlay
  types.ts               // shared interface
```

The screen just imports `./player/Player` and uses the interface. Adding a platform means adding a file, not editing every screen. The same pattern works for keys (`keys.tizen.web.ts`), device info, storage, and app lifecycle.

Small differences (a number, a flag) can live in a config module chosen the same way (`config.tizen.web.ts`) instead of `if`s.
