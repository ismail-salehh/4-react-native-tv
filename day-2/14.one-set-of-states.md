# One set of states

Every screen that loads data has the same four non-happy states. Build them **once** as shared components, so every screen behaves the same way.

| State | Shows | Focus |
| --- | --- | --- |
| **Loading** | Skeleton cards in the real layout (not a full-screen spinner) | Keep focus on a safe element that stays mounted (the menu, or the previous content) |
| **Empty** | Short message ("No results for 'abc'") + a useful next step | On the next-step button ("Browse popular") |
| **Error** | Short message, no stack traces or codes in big letters | On **Retry** |
| **Offline** | "You're offline" + what still works | On **Retry**; also retry automatically when the network returns |

```tsx
<ScreenState
  state={query.state}            // 'loading' | 'empty' | 'error' | 'offline' | 'ready'
  onRetry={query.refetch}
  emptyMessage="No results"
>
  <Rails data={query.data} />
</ScreenState>
```

Rules:

- **Every error and offline state has a focusable Retry** with initial focus (`hasTVPreferredFocus` / `setFocus`). Otherwise the user is stuck on a screen where nothing is focused and only Back works.
- **Back still works** from every state.
- **Don't replace focused content with a spinner** on refresh. That unmounts the focused element and loses focus (see [Lost focus](../docs/02-remote-and-focus.md#dead-ends-traps-unexpected-jumps-lost-focus)).
- Errors inside one rail (one failed request) should fail that rail only, not the whole screen.
