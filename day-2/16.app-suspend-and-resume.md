# App suspend and resume on TV

The user presses Home, switches input to a game console, or the TV goes to standby. Your app is suspended, and later resumed, maybe hours later.

How each platform tells you:

| Platform | Signal |
| --- | --- |
| Android TV, Apple TV | `AppState`: `'active'` ↔ `'background'` |
| LG webOS (web) | `visibilitychange` (`document.hidden`); `webOSRelaunch` when the app is opened again while still running |
| Samsung Tizen (web) | `visibilitychange` (`document.hidden`) |

```tsx
// native
useEffect(() => {
  const sub = AppState.addEventListener('change', state => {
    if (state === 'active') onResume();
    else onSuspend();
  });
  return () => sub.remove();
}, []);

// web
document.addEventListener('visibilitychange', () => {
  document.hidden ? onSuspend() : onResume();
});
```

**On suspend:**

- Pause playback and save the position ("continue watching").
- Stop polling, timers, and animations.
- Some players need to release or suspend the decoder (e.g. Samsung AVPlay); check the player docs.

**On resume:**

- **Refresh auth** if the token may have expired.
- **Refetch stale data** (rails, live channel info), without unmounting the focused content.
- **Check focus.** On web, focus can be lost after resume. Re-apply the last focus key or the screen's initial focus.
- Restore the player, or show the paused player with a focused Play button. Don't auto-play with sound after hours away.
- Reconnect sockets and restart polling (e.g. device code login).

> **Verify (web):** check the current LG and Samsung docs for lifecycle events (`webOSRelaunch`, Tizen app lifecycle and multitasking, AVPlay `suspend`/`restore`), and test Home → reopen and standby → wake on a real TV.
